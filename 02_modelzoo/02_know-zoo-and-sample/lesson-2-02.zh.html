What Is It

Model Zoo 是什么

地瓜机器人维护的 BPU 模型示例集合。当前交付线是 main 分支（仓库 VERSION 2.0.0）。

转换好的模型

已编译的 .bin / .hbm，下载即用。

板端推理代码

Python 入口，前后处理已写好。

转换与评估

conversion/ 转换，evaluator/ 评估。

一条主线

main 统一维护；rdk_x5、rdk_s 保留为历史分支。

先说 Model Zoo 是什么。它是我们维护的 BPU 模型示例集合。每个 Sample 里，有转换好的模型、板端推理代码，还有转换配方和精度评估。过去不同板卡各有分支，现在 main 分支统一维护，当前版本是 2.0.0；历史上按板卡分的 X5 分支和 S 系列分支仍然保留。

认识 RDK Model Zoo · 选板流程07 / 26
重点来了：一套代码，怎么跑四块板。Sample 代码只有一份。你用 target 参数告诉它在哪块板上跑，可以写 x5、s100、s100p、s600，也可以写 auto。写 auto 时，程序读取板卡身份，对照 platforms 对照文件，认出目标。目标定了，制品也就定了：X5 用 bayese 的 .bin，S100 用 nashe 的 .hbm，S100P 用 nashm，S600 用 nashp。代码不变，变的只有 target 和制品。

Artifact Selection

制品怎么选对

三个概念，决定了到底跑哪个文件。

manifest 清单

docs/release 里每个制品一行，地址和格式以它为准。

asset-id 与路径

asset-id 是清单里的名字，model-path 是本地文件，须配对。

运行前校验

target 与检测到的硬件不一致，直接报错。

RDK 小课堂 2-02
认识 RDK Model Zoo · 制品选择14 / 26
怎么保证跑的是对的文件？三个概念。第一，manifest，也就是 docs 下 release 里的清单，每个制品一行，下载地址和格式以它为准。第二，asset-id 和 model-path：asset-id 是清单里的完整名字，model-path 是本地文件，两者必须配对，因为只看文件名，分不出输入协议。第三，运行前校验：请求的 target 和检测到的硬件不一致，程序直接报错，不会硬跑。
Input Protocol

两种输入协议

RDK X5

packed NV12

  • 一个输入张量
  • 一维 uint8 缓冲
  • 224×224：75,264 字节
  • 制品格式 .bin
VS
S100 · S100P · S600

split NV12

  • Y 和 UV 两个输入
  • Y：(1,224,224,1)
  • UV：(1,112,112,2)
  • 制品格式 .hbm
RDK 小课堂 2-02
认识 RDK Model Zoo · 输入协议15 / 26
同一份代码能跑四块板，还因为前处理会按输入协议准备数据。X5 的模型只有一个输入，是 packed NV12，一维的 uint8 缓冲，224 乘 224 的图像是 75,264 字节。S 系列的模型有两个输入，Y 和 UV 分开：Y 是 1、224、224、1，UV 是 1、112、112、2。你不用自己拼；输入张量用 model_info 核对，输入协议用 dry-run 参数看。

Pitfalls

常见五个坑

跑不起来时，先查这五项。

  • ✕S100P 不能用 S100 制品
  • ✕target 与硬件不符会报错
  • →老镜像可能缺 PyYAML/Pillow
  • →推理不自动下载，先下载制品
  • !C++ 默认 zebra，看白狼加参数
RDK 小课堂 2-02
认识 RDK Model Zoo · 常见坑25 / 26
最后说五个常见的坑。第一，S100P 不能用 S100 的制品，两者的 march 不同。第二，target 和检测到的硬件不一致，程序直接报错。第三，老镜像或精简镜像可能缺 PyYAML、Pillow，用 pip 装上即可；两块板上都已经具备，没有缺依赖。第四，推理不会自动下载模型，要先运行 download.sh。第五，S 系列的 C++ run.sh 默认用 zebra 图，看白狼必须加 test-img 参数。
