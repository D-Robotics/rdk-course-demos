Demo 01 · Prompt

先让 Moss 做只读体检

对象、范围、安全边界和输出格式一次说清。

一条完整任务

请对当前连接的 RDK X5 做一次只读设备体检。检查设备与 SSH 状态、CPU、内存、温度、磁盘和网络，只读取信息，不安装软件、不修改配置、不重启服务。

最后按“正常、需关注、建议处理”给出结论，并列出实际检查项目。

明确安全边界

只读取信息 不安装软件 不修改配置 不重启服务

失败项必须标为未验证，不能猜测。

Demo 01 · Result

六项结果必须能够核对

连接

设备与 SSH 明确成功、失败或未验证。

CPU

检查负载或占用概况。

内存

核对总量、已用和可用空间。

温度

读取当前关键温度。

磁盘

检查主要分区与剩余空间。

网络

说明接口与连通状态，不公开真实地址。

Demo 02 · Prompt

一句话启动 BPU YOLO

不指定仓库和命令，只明确设备、算力、输入与最终结果。

任务对象与算力

在当前连接的 RDK X5 上，使用 X5 BPU 运行 YOLO 实时目标检测。

推理必须运行在 BPU，而不是 CPU。

输入与最终结果

使用连接在 X5 上的 USB 摄像头。启动后，在 RDK Studio 内置浏览器中打开实时检测页面。

Moss 自主选择成熟方案。

Demo 02 · Success

这六项必须同时成立

日志、单张图片或 CPU 推理都不能替代实时 BPU 结果。

  • 执行设备是当前连接的 RDK X5
  • YOLO 推理由 X5 BPU 执行
  • 输入来自连接在 X5 上的 USB 摄像头
  • Studio 自动打开内置浏览器
  • 浏览器持续显示实时摄像头画面
  • 画面出现检测框和类别结果

Safety

高风险操作先核对六件事

安装、改网、重启、覆盖文件、烧录和外发信息都需要明确确认。

  • 目标设备是否正确
  • 目标路径或介质是否正确
  • 影响范围是否清楚
  • 重要数据是否已经备份
  • 回退方式是否可执行
  • 完成后的验证方法是否明确
FAQ

四个概念不要混淆

Moss ≠ 模型

Moss 组织任务与工具，模型提供推理能力。

Codex ≠ Studio

Codex 是可选外部 Agent，不是 RDK Studio 后端。

串口 ≠ SSH

串口读取日志，完整工作区需要 SSH 或受支持的 Type-C。

板端 Agent 可选

终端、文件、IDE 和常规 Moss 任务不依赖板端 Agent。
