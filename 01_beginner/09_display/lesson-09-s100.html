Before You Start

Prepare a Stable Recording Setup

This S100 lesson verifies HDMI only; it does not include a DSI workflow.

  • Prepare the S100, HDMI monitor, HDMI cable, and stable power
  • Select the correct monitor input and keep key ports clearly visible
  • Enter new_project and run source env.sh
  • Keep ROS_DOMAIN_ID at 42 and use only ports 9100–9199
  • Keep the GNOME / X11 desktop awake throughout recording
  • Keep SSH and VNC enabled; do not change networking or unrelated system projects

Stable Recording

The Recording Environment Is Part of Success

A lock screen or sleep event is not an HDMI link failure.

Step 1

Disable GNOME idle timeout, automatic dimming, screen lock, and DPMS.

Step 2

Attach x11vnc to the real :0 session; VNC should match HDMI.

Step 3

Keep the desktop awake so the camera does not capture a lock screen.

Step 4

After the demo, confirm SSH, VNC, and the desktop session still work.

Completion Checklist

Six Results Together Define a Pass

The display must look correct, reproduce reliably, and exit without side effects.

  • DRM and X11 both report HDMI-1 as connected
  • The active mode is 1280×720 at 60.00 Hz
  • Color, grayscale, text, fine lines, geometry, and motion pages are visible
  • runtime.json records result=PASS
  • Ports 9100–9199 are released with no project process left behind
  • SSH, VNC, and the always-on desktop remain available
Troubleshooting

Separate Signal, Desktop, and Demo Faults

No monitor signal

Check the input source, cable, and power before reading DRM status.

Screen turns black

Check screen lock, sleep, and DPMS before changing HDMI settings.

Black VNC view

Confirm VNC uses the real X11 session and the correct Xauthority.

Demo fails

Inspect terminal safety checks, runtime.json, and server.log.
