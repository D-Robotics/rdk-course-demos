Lesson Mission

本课要完成什么

Server 与 Client 都运行在同一块 X5 上，先排除外部网络变量

RDK X5

适用于 X5 4GB、8GB；Module 需配套 Camera 与 HDMI 载板

Camera 输入

以 IMX219 为例，采集 1920×1080@30fps NV12

H.264 传输

硬件编码目标 8000 kbit/s，经本机 RTSP/TCP 传输

可见结果

VPS 缩放为 800×480，由 Display channel 1 输出到 HDMI

End-to-End Pipeline

一条完整的视频链路

Camera / ISPBayer RAW → NV12
硬件编码NV12 → H.264
RTSP / RTP127.0.0.1:8554/live
硬件解码H.264 → NV12
VPS / HDMI1080p → 800×480

Before You Start

开始前准备好这些

板卡与系统

RDK X5 与受支持的 RDK OS，BSP 编解码驱动可用

MIPI Camera

使用 BSP 支持的传感器；调整排线前必须先断电

HDMI 屏幕

支持 800×480；先给屏幕供电并选中 HDMI，再启动 X5

两个终端

一个运行 Server，另一个运行 Client，便于独立观察日志

Preflight Checks

四项环境检查

先确认板卡、驱动、显示模式和开发接口，再进入编译

① 型号与驱动

cat /proc/device-tree/model && ls -l /dev/vpu /dev/jpu 2>/dev/null

型号应包含 RDK X5，编解码设备节点应存在

② HDMI 模式

cat /sys/class/drm/card*-*/status && grep -x '800x480' /sys/class/drm/card*-*/modes

至少一个 HDMI connector 为 connected，并支持 800x480

③ BSP 接口

test -f /usr/include/sp_codec.h && ldconfig -p | grep libspcdev

确认头文件与 libspcdev 已由 BSP 提供

④ GStreamer

gst-inspect-1.0 appsrc && gst-inspect-1.0 rtspsrc && gst-inspect-1.0 rtph264pay

继续检查 appsink、h264parse 与 rtph264depay

Build on Board

在板端完成编译

在 X5 本机重新配置和链接，不复制其他架构的可执行文件或动态库

① 安装依赖

sudo apt install -y build-essential cmake pkg-config libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev libgstrtspserver-1.0-dev

补齐编译工具、GStreamer 与 RTSP Server 开发包

② 配置

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release

在 01_beginner/10_codec 目录执行

③ 编译

cmake --build build -j2

X5 4GB 建议使用 -j2，降低峰值内存

④ 验证产物

./build/codec_rtsp_server --help && ./build/codec_rtsp_client --help

应生成 Server 与 Client 两个可执行程序

Why Codec Matters

为什么要编解码

原始数据很大

1080p NV12 每帧 3,110,400 bytes，30fps 约 746.5 Mbit/s

编码降低带宽

硬件编码压缩到约 8 Mbit/s，并生成 SPS、PPS 与 IDR

解码恢复图像

压缩码流不能进入 VPS；先 RTP depay，再硬件解码为 NV12

API Responsibilities

每一层只做一件事

Camera / VIO

sp_open_camera_v2 打开 Camera、ISP 与 NV12 输出

Encoder

sp_start_encode 创建 H.264 硬件编码通道

GStreamer

负责 RTP 打包、RTSP 会话、拉流与解包，不解码图像

Decoder

sp_decoder_set_image 把 H.264 访问单元送入 VDEC

VPS

sp_open_vps 将 1920×1080 NV12 缩放为 800×480

Display

sp_start_display 通过 X5 channel 1 输出 HDMI

Parameter Boundaries

三组参数不能混淆

码流尺寸必须前后一致，屏幕适配由 VPS 完成

Sensor 尺寸

Server --sensor-width/--sensor-height：Camera RAW 输入尺寸

Codec 尺寸

两端 --width/--height：编码和解码都保持 1920×1080

Display 尺寸

Client --display-width/--display-height：最终输出 800×480

RTSP Server

先启动编码端

启动 Server

sudo ./build/codec_rtsp_server --codec h264 --width 1920 --height 1080 --sensor-width 1920 --sensor-height 1080 --fps 30 --bitrate 8000 --camera-index -1 --pipe-id 0 --port 8554 --mount /live

在第一个 X5 终端运行；-1 表示自动探测 Camera

本机拉流地址

rtsp://127.0.0.1:8554/live

课程首次验收固定使用回环地址

Camera 日志

[camera] sensor=1920x1080 output=1920x1080 fps=30

确认分辨率、帧率和编码器配置正确

发布指标

published ↑ push-fail=0 SPS/PPS/IDR > 0

Client 连接前 no-client 增加属于正常现象

RTSP Client

再启动解码显示端

保持 Server 运行，在第二个终端接管 HDMI 显示资源

Step 1

确认 HDMI 为 connected，模式列表包含 800x480

Step 2

执行 sudo systemctl stop display-manager

Step 3

运行 Client：--url rtsp://127.0.0.1:8554/live --width 1920 --height 1080 --display-channel 1 --display-width 800 --display-height 480 --duration 30

Step 4

等待 30 秒测试自然结束，再停止 Server

Completion Checklist

这样才算真正成功

PASS 只说明管线已初始化并提交数据，最终结果必须用 HDMI 画面验收

  • Server 的 encoded 与 published 按约 30 次/秒增长
  • push-fail=0，H.264 的 SPS、PPS、IDR 均大于 0
  • Client 出现 linked H264 RTP pad
  • received 与 submitted 按约 30 buffer/s 增长
  • 日志显示 Display 800x480 channel=1
  • 屏幕连续显示实时画面，比例、方向、颜色正确且无持续黑屏
Troubleshooting

按链路定位故障

编译慢或内存紧

X5 4GB 使用 cmake --build build -j2

Camera 打不开

断电检查排线、传感器支持和 VIO 占用

VPU 初始化失败

检查设备节点、内核模块、dmesg 与 BSP 版本

Connection refused

确认 Server 监听 8554，URL 完整匹配 /live

PASS 但黑屏

停止桌面服务，并显式指定 channel 1 与 800×480

提前收到 EOS

保持 Server 运行，等待 Client 自然结束后再停止
