# RDK S100 远程连接口播稿

系统烧录完成，开发板也能正常启动以后，下一步就是从电脑远程登录 RDK S100。

以后的代码修改、程序运行和日志查看，基本都可以在电脑上完成。开发板不需要一直外接显示器、键盘和鼠标。

第一次连接时，我建议先把串口打通。这样即使网络还没配好，我们也能看到启动日志，进入系统检查网络状态。

课程里如果提到 Flash-Link，这一步实际用到的是 J16 Type-C 接口提供的调试串口，不要把它理解成网口。这个接口通过两颗 CH340 芯片，分别接出了 Main 域和 MCU 域的调试串口。我们现在要登录 Ubuntu，所以要选择 Main 域对应的串口，也就是能看到 Linux 启动日志的那个端口。

先用一根支持数据传输的 Type-C 线，把电脑和开发板的 J16 接口连起来。第一次连接时，电脑可能需要安装 CH340 驱动。驱动正常以后，在 Windows 设备管理器里会看到新增的 COM 端口。

这里以 MobaXterm 为例。新建一个 Serial 会话，选择刚才识别到的 COM 端口。波特率设置为 921600，数据位 8，校验位 None，停止位 1，流控选择 None。

连接以后按一下回车，终端里应该能看到登录提示。如果窗口里完全没有输出，可以换另一个新出现的 COM 端口再试。看到的如果是一串乱码，先检查波特率是不是 921600，再检查 CH340 驱动是否安装正确。

系统默认提供两组账号。普通用户的用户名和密码都是 sunrise，管理员的用户名和密码都是 root。这一步我们先用 root 登录，用户名输入 root，密码也输入 root。输入密码时，终端不会显示星号或其他字符，这是正常现象，输完直接回车就可以。

登录成功以后，执行下面这条命令查看网络接口。

```bash
ifconfig -a
```

在输出里找到 eth1。RDK S100 的 eth1 默认使用静态地址，IP 是 192.168.127.10，子网掩码是 255.255.255.0，网关是 192.168.127.1。

接下来连接有线网络。RDK S100 上有两个 RJ45 网口，这里把网线插到靠外侧的网口，这个网口在系统里对应 eth1。网线另一端直接连接电脑。

开发板的地址已经固定好了，电脑也要手动设置到同一个网段。打开 Windows 的网络连接，找到这根网线对应的以太网适配器，进入 Internet 协议版本 4 的属性页面。

电脑的 IP 可以填写 192.168.127.100，子网掩码填写 255.255.255.0，默认网关填写 192.168.127.1。注意，电脑和开发板必须在同一个网段，但不能使用同一个 IP，所以电脑不要填写 192.168.127.10。

设置完成后，打开 PowerShell，先测试网络是否连通。

```powershell
ping 192.168.127.10
```

看到来自 192.168.127.10 的回复，说明电脑已经能访问开发板。如果这里一直超时，先检查网线是不是插在靠外侧的 eth1 网口，再检查电脑的 IP 和子网掩码，不要急着继续做 SSH 登录。

网络确认正常以后，在 PowerShell 里输入下面这条命令。

```powershell
ssh sunrise@192.168.127.10
```

第一次连接时，终端会询问是否信任这台设备，输入 yes 并回车。接着输入密码 sunrise。这里输入密码同样不会显示字符，输完直接回车。

看到 sunrise@ubuntu 的命令行提示符，就说明 SSH 已经连接成功。可以再执行两条命令确认当前用户和 eth1 的地址。

```bash
whoami
ip addr show eth1
```

如果开发板重新烧录过，电脑提示远端主机身份发生变化，可以先删除旧的 SSH 记录，再重新连接。

```powershell
ssh-keygen -R 192.168.127.10
```

到这里，RDK S100 的远程连接就完成了。平时改代码、传文件和运行程序，优先使用 SSH。串口保留着，需要查看启动过程，或者网络出现问题时，再回到串口排查。
